How a trade flows

1 · Analyst agentReads order books through MCP tools and proposes trades as JSON. It is never shown the order tool.
2 · Risk agentDry-runs each proposal with check_order, then approves, resizes or rejects it.
3 · Execution agentThe only agent allowed to call place_order. A hook enforces this, whatever the prompts say.
4 · Risk gate (code)Checks every order against hard limits inside the MCP server, before the C++ engine sees it.
5 · C++ matching engineOn advance_time, matches bids against asks at this step's book and settles the wallet.
Built by CI from the latest run on main. Data: real order-book snapshot from 17 March 2020.
